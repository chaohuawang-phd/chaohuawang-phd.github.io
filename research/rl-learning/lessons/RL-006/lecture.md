## 1. 今天解决什么问题，与前面哪些单元有关

前五课已经有了描述决策的语言：任务中的观测、状态、动作、反馈与回报；策略如何改变数据；V、Q 对什么取期望；Bellman 方程怎样把一步与未来连接起来。今天不增加一个算法名字，而是把这些概念用于判断：**研究任务究竟需要学习什么决策，现有数据能支持什么结论？**

“用 RL 提高 SR 质量”“训练一个模态路由器”“让 GUI Agent 完成任务”都只是方向。它们尚未说明哪些量在决策前可见、动作改变什么、反馈来自哪里，以及什么基线足以解决问题。先把这些条件写清楚，才能判断监督学习、单步反馈框架、规划或多步 RL 各自是否适合。

本课先为 SR、模态路由、GUI 分别作结构判断，再选择“按指令修改指定设置并持久保存”的多步 GUI 草案深入填写。**选择 GUI 只是因为 RL-004～005 已有同一教学环境，便于连贯练习，不代表研究优先级，也不代表已经确认的真实业务定义。**

真实资料没有提供的地方统一写 **【待确认】**。这是任务说明中的空缺，不应由教学概率、别处的标签合同或模型猜测替代。本课不会开展真实操作、线上探索、模型训练或性能实验。

## 2. 学习目标

学完后，应当能够：

1. 分别判断普通一次 SR 重建、模态路由、单次 GUI 定位与多步执行的决策结构，指出多步 RL 是否有明确的讨论对象。
2. 写出一个可填写、可检查的工程任务合同，覆盖输入、合法动作、回报、反馈、期限、数据、成本和非 RL 基线，保留未知信息。
3. 用前课同一模型检查“策略、预算和评价目标是否一致”，区分教学差值、工程推断、研究假设和真实实验结果。

## 3. 直觉、定义和必要公式

### 3.1 什么叫“决策说明”

决策说明是一份让研究者、执行器和评价程序使用同一任务定义的合同。它不是算法宣传页，也不要求提前知道真实环境的全部转移概率。

一份说明至少能回答五个问题：

1. **何时、根据什么信息做决定？** 只能使用选择当时真实可得的观测，不能偷用未来反馈。
2. **可以做什么，做了会改变什么？** 输出坐标、选择分支、选择停止，语义与合法范围都应明确。
3. **怎样知道做得好？** 区分监督目标、选中动作的评价、最终结果和未观察的反事实。
4. **一次决定之后是否还有受影响的决定？** 动作会不会改变后续信息、状态、合法动作或共享资源？
5. **什么简单方法也能解决，公平比较需要固定什么？** 不先写基线，就容易把额外信息、计算或更宽预算当成算法贡献。

只要输出能被称为动作，并不意味着训练就是 RL。反过来，任务具有多步结构，也不意味着一定要用 RL：规则、示范学习、已知模型规划都可能足够强。

单步奖励与 Bandit 也可以放在广义 RL 的框架中讨论，**没有多步影响，不等于绝不能采用 RL 方法**。本课要区分的是决策、反馈与代价的结构，避免在单步任务上无理由地增加多步算法与训练成本。

### 3.2 分别为三类研究任务作结构判断

| 方向与设定 | 当下要预测或选择什么 | 反馈与时间结构 | 优先检查的起点 |
|---|---|---|---|
| SR：普通一次重建 | 给定低分辨率图像，输出一次高分辨率重建 | 有配对目标时可直接监督；网络内部有多层并不等于存在任务级序列决策 | 相同数据和计算预算的监督 SR；图像退化、质量指标与泛化 |
| SR：早停、迭代或计算分配 | 是否继续计算、运行哪一步或给哪个区域分配计算 | 如果动作改变之后可得的质量、预算和可选操作，才出现具体序列问题 | 先确认动作接口、决策时可见质量线索、质量—成本目标、固定预算及简单停止规则 |
| 模态路由：一次选分支后结束 | 从实际允许的处理分支中选一个 | 若请求互不影响且没有继续决策，可先讨论成本敏感监督；只有选中动作反馈时涉及 contextual bandit | 实际输入、标签、动作与成本全部【待确认】；先比较固定分支、规则和匹配的监督模型 |
| 模态路由：获取信息后继续决定 | 是否获取输入、再调用分支、重试或使用共享预算 | 只有确认动作确实改变后续信息、动作或资源，才具体定义多步问题 | 不凭“路由”名称认定是 MDP；先写时间结构与反馈可得性 |
| GUI：一次理解或控件定位 | 由指令与允许输入预测控件或坐标 | 有正确框、坐标或元素标签时，可先监督训练和离线定位评价 | 命中率、定位误差与实际输入权限；没有执行环境也能做监督定位 |
| GUI：多步操作 | 连续选择点击、输入、滚动、返回、结束等 | 当前动作改变后续页面与完成机会，需要任务级反馈与期限 | 先建可执行、可重置、可核实结果的合同，再比较规则、示范学习和必要的多步方法 |

**SR 的边界。**网络有迭代层、多个出口，甚至输出了一个“停止分数”，都不自动说明 RL 有必要；监督学习、直接优化或简单阈值也可能训练这些部件。只有明确了可执行决策、可用反馈及其相对优势，才继续论证。部署时通常没有真实高分辨率目标，不能让停止策略提前看到评测用的真值误差。SRCNN 的原始作者提交页明确描述从低分辨率到高分辨率的端到端映射，支持“一次重建可先按监督映射理解”这一任务起点；本课不引用其性能作为当前方案的效果。[SRCNN 原始论文](https://arxiv.org/abs/1501.00092)

**路由的边界。**本课不把其他任务的标签定义、输入设备、图像来源或回退规则当成当前实际合同。标签究竟标“输入是否必要”“推荐哪条分支”“答案是否正确”还是其他含义，都为 **【待确认】**，且这几种含义不能互相替代。选择前能否看到图像、只能知道图像是否存在、还是获取图像本身也要付费，同样需要确认。

如果日志只显示选中分支的反馈，未选分支仍是未知，不能自动填成错误或正确。若有可信的全动作结果，可以考虑成本敏感监督或直接比较；如果结果仅来自选中动作，则先承认反馈不完整。行为策略的实际选择概率有助于描述数据，但只记录概率并不能自动完成反事实评估。

**GUI 的边界。**单帧定位命中不等于设置被持久保存。真实网站动作序列可由示范数据学习，不能因为有多步任务就把已有数据处理叫作 RL。Mind2Web 的原始作者提交页描述了语言任务与人工动作序列，并说明其方案使用网页 HTML；这是一个任务/数据参考，不是本课纯截图方案的既有实验，也不能直接类比桌面应用权限或真实执行成功。[Mind2Web 原始论文](https://arxiv.org/abs/2306.06070)

### 3.3 回报必须对应同一任务合同

沿用前课：在 t 时刻执行 a_t，随后收到 r_(t+1)。有限、真实结束的任务，目标可以写为：

\[
G_0=\sum_{t=0}^{T-1}\gamma^t r_{t+1},
\qquad J(\pi)=\mathbb E_{\tau\sim\pi}[G_0]
\]

- T：本次任务真实结束前的动作数，最后一个奖励为 r_T；不是外部采集器任意截取的长度。
- t：从 0 开始的动作时间索引。
- r_(t+1)：当前动作之后按已约定规则得到的奖励。
- γ：折扣因子，表达目标中的时间权重；真实任务取值 **【待确认】**。
- G₀：一条完整轨迹的折扣回报；J(π) 是指定任务分布与环境下策略 π 的期望回报。
- τ：包含观测或状态、动作、奖励和起止信息的一次任务轨迹；期望还涉及初态、策略与环境随机性。

真实 GUI 可以讨论“独立验证的完成收益减过程成本”这一奖励草案，但成功定义、收益数值、错误代价和换算权重均为 **【待确认】**。毫秒、金额和风险不能不经定义就直接相减；可以先分别报告质量与成本，在明确换算或预算约束后再讨论统一回报。模型自称成功或置信分数上升，不自动等于任务奖励可信。

V_h^π(s) 仍表示从给定状态与剩余预算开始按 π 执行的期望回报，Q_h^π(s,a) 则先指定动作 a 再按 π 继续。对真实部分可观测 GUI，不因为写出 s 就证明完整状态可见；观测、合法历史与隐藏状态要分别讨论。上述基础概念可核对 [Spinning Up 官方入门](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html)；本课的合同与研究判断是工程分析。

## 4. 手算检查：只复用 RL-004～005 的已知教学模型

### 4.1 条件完整列出，避免把不同环境混着比较

**本节所有精确数字都是教学假设，不是实际 GUI 成功率、成本或训练结果。**原封不动复用 RL-004～005 的新环境，不采用 RL-002 的另一套打开失败率和保存奖励。

页面 H 是主页，F 是准备好的表单，z 是终态；完整理想状态为 (页面,剩余真实动作数 h)。初态为 (H,2)，γ=0.9。

| 页面及合法动作 | 后果 | 当前奖励 | 环境概率 |
|---|---|---:|---:|
| H, open | 到 F，预算减 1 | −1 | 1.00 |
| H, stop | 到 z | 0 | 1.00 |
| F, save | 成功，到 z | 10 | 0.80 |
| F, save | 失败，到 z | 0 | 0.20 |
| F, cancel | 到 z | 0 | 1.00 |

每个页面—动作组分别归一；每个真实动作消耗一步。save 不另扣成本。预算耗尽就真正结束，未完成没有额外罚分，也不补发成功奖励；终态之后追加的奖励为 0。

| 给定策略 | H：open / stop | F：save / cancel |
|---|---|---|
| πα | 0.75 / 0.25 | 1.00 / 0.00 |
| πβ | 0.75 / 0.25 | 0.50 / 0.50 |

这些概率用于 h>0 的合法决策点。h=0 没有真实动作；教学模型理想地把页面与预算视为充分状态，真实截图不自动满足这一假设。

### 4.2 固定预算比较给定策略

从 (F,1) 开始，save 的平均奖励为 0.8×10+0.2×0=8，cancel 为 0；因而 V₁πα(F)=8、V₁πβ(F)=4。

强制从 (H,2) 执行 open，后续分别按两种策略：

\[
Q_2^{\pi_\alpha}(H,\mathrm{open})=-1+0.9\times8=6.2,
\qquad Q_2^{\pi_\beta}(H,\mathrm{open})=-1+0.9\times4=2.6
\]

Q 已经指定首动作，所以不再乘选择 open 的 0.75。V 需要对第一步 open 与 stop 平均：

\[
V_2^{\pi_\alpha}(H)=0.75\times6.2+0.25\times0=4.65,
\qquad V_2^{\pi_\beta}(H)=0.75\times2.6+0.25\times0=1.95
\]

同模型、同初态、同奖励和两步预算下，两者期望回报差为 4.65−1.95=**2.70 个教学回报单位**。它不是成功率增加 2.70 个百分点，更不是实际 GUI 的性能提升。两种策略是给定行为，没有在本课训练出来。

### 4.3 改变预算，就是改变价值条件

若只剩一步，open 消耗最后预算，未来没有 save：

\[
Q_1^\pi(H,\mathrm{open})=-1+0.9V_0^\pi(F)=-1,
\qquad V_1^{\pi_\alpha}(H)=V_1^{\pi_\beta}(H)=-0.75
\]

此时 stop 的回报为 0，所以教学模型的最优选择是 stop，V₁*(H)=0；剩两步时最优 open 后 save，V₂*(H)=6.2。指定 πα 虽在 F 最优保存，在 H 仍随机 stop，所以其 V₂=4.65 不是最优价值。

这段手算用于检查合同：是否写明后续策略、剩余预算、终止与奖励？若把两步方案的 4.65 和一步方案的 −0.75 当作公平算法对照，就混入了任务预算差异。若真实日志只是外部停止记录，不能套用本模型 h=0 的零未来边界。

## 5. 与前一种方法或概念的关系

前五课主要问“给定一个模型，量是什么意思、如何计算”；今天问“真实问题中，这些量和条件是否已被正确提供”。没有引入新的训练算法。

| 已有知识 | 今天转成的工程问题 | 新增代价或限制 |
|---|---|---|
| RL-001：奖励与回报 | 什么算真正成功，成本怎样计量？ | 需要独立结果验证与单位说明 |
| RL-002：状态、转移与起止 | 真实观测是否充分，动作怎样执行和重置？ | 需要接口、边界和隐藏变量分析 |
| RL-003：策略影响数据 | 哪些动作被采过，哪些反馈缺失？ | 需要行为日志与覆盖检查，不能伪造反事实 |
| RL-004：V、Q 与 h | 评价的是哪个后续策略和预算？ | 策略版本、任务期限与初态必须对齐 |
| RL-005：一步与未来 | 未来后果是否真的存在、如何获得可信证据？ | 方程本身不提供未知转移、数据或业务增益 |

把任务写成 MDP 不要求已经知道精确 p；但精确手算或模型规划需要可信模型。真实 p 未知时，仍要收集数据并选择合适估计方法。单步问题不必为了使用 Bellman 方程而制造无意义的下一状态。

## 6. 主要应用：可填写的多步 GUI 工程任务合同

### 6.1 草案的目的与事实边界

**拟议问题：按语言指令修改一个指定设置，并确认该值已持久保存。**这是本课工程练习题，不是已确认的实际应用。本节选择它，是因为与前课教学环境衔接；不意味着用户其他研究方向的重要性较低。

以下表格可以逐项填写，右栏在获得真实资料之前保留 **【待确认】**。左栏的建议字段和候选内容属于工程推断，不能当作系统已经具备的功能。真正的任务合同还应有版本、负责人或资料来源和确认日期。

### 6.2 一份可以复用的任务说明表

| 合同字段 | 应填写的定义与检查办法 | 当前真实资料 |
|---|---|---|
| 任务与适用范围 | 应用/平台、要修改的设置、允许的目标值、完成条件；区分一次定位和完整操作 | 【待确认】应用、设置与任务分布 |
| 决策时点 | 何时允许选择下一动作，动作是否已完成，异步加载何时结束 | 【待确认】执行反馈与等待规则 |
| 选择前可见输入 | 指令、截图、可用历史；是否允许 DOM、可访问树、接口状态及其来源 | 【待确认】实际输入来源与权限；不可提前读取未来结果 |
| 状态假设 | 焦点、登录、加载、页面进度与剩余预算是否影响后果；哪些可见、哪些隐藏 | 【待确认】可观测性；不能默认截图 Markov |
| 合法动作与参数 | 点击/输入/滚动/返回/取消/结束；坐标系、目标元素、文本与失败返回语义 | 【待确认】实际执行接口和合法范围 |
| 动作后果与模型 | 下一观测、执行是否生效、失败和延迟；p 未知可明确未知 | 【待确认】数据来源；不填入教学 p=0.8 |
| 初态与重置 | 设置初值、账户/页面条件、任务如何抽样、怎样恢复初态 | 【待确认】重置机制与评价初态分布 |
| 终止与期限 | 成功、失败、取消、真实动作/时间预算；外部采集截断单独记录 | 【待确认】任务内预算、结束信号与截断原因 |
| 奖励与单位 | 独立完成收益、操作/调用/错误成本、γ、成本换算或约束；成功只计一次 | 【待确认】业务目标与代价，不套用收益 10 或 open 成本 1 |
| 可信反馈来源 | 保存后回读目标值或可核查持久状态，必要时人工复核；训练评分与最终验证分开 | 【待确认】验证接口、延迟、噪声及复核方式 |
| 数据与版本 | 任务ID、决策前输入、允许历史、合法动作、策略/执行器版本、实际动作、结果与成本 | 【待确认】现有日志覆盖和数据版本 |
| 轨迹与反馈完整性 | 下一真实观测、奖励、剩余预算、终止/截断、最终结果；保留失败与取消，重置不接旧轨迹 | 【待确认】缺失字段与可恢复性 |
| 评价指标 | 任务级成功率和回报；步骤、非法动作、超时/截断、调用与费用、端到端时延；分组与不确定性 | 【待确认】评价集、任务分组与测量办法 |
| 非 RL 基线 | 固定流程/有限状态机、规则加监督定位、示范学习；已知模型时枚举或搜索 | 【待确认】可运行的实现与资源 |
| 训练成本 | 交互采样、环境重置、反馈验证、示范收集、标注和优化计算 | 【待确认】样本、调用、标注与计算预算 |
| 推理成本 | 每步模型和工具调用、搜索/价值估计、执行等待、重试与结果验证 | 【待确认】每任务总费用、耗时及资源限制 |
| 公平比较条件 | 固定任务分布、输入权限、底层模型、动作集合、预算、重置与成功验证；不同资源方案单列 | 【待确认】预先固定的评价协议 |

“状态”可以先写成“截图与合法历史形成的近似表示”，并保留隐藏变量假设；不能仅因输入了历史就宣称 Markov 性已证明。行为选择概率如果能正确取得，应对应真正执行的采样、动作屏蔽与回退规则；无法取得时记录未知，不拿事后分数冒充。

### 6.3 最小数据与结果验证该怎样检查

对同一次任务，至少应能还原“决策前看到什么 → 实际做什么 → 环境返回什么 → 为什么继续或结束”。必须保留失败、放弃和中断，避免只用成功演示估计所有策略的价值。策略或执行器升级后，版本必须可追溯；不能把不同后续行为默认为同一个 π。

“点击了保存”是动作，“出现保存提示”是一次观测，“重新读取后目标值仍正确”才可能成为持久保存的验证依据。真实验证方式仍为 **【待确认】**。若验证器只检查视觉提示，就应承认它评价的是提示出现，而不提前声称持久状态正确。

静态演示数据可以支持监督学习、模仿或离线动作预测；不因保存成轨迹格式就自动支持任意新策略的可靠离线评估，更不能给从未执行的动作补结果。Mind2Web 的数据/任务形式可以作为参考，但其 HTML 信息条件与真实截图控制权限需要分别核对。

### 6.4 最小比较协议与研究假设

先在相同输入、底层模型、任务与预算下比较固定流程/有限状态机、规则加监督定位、示范学习执行器。模型可信已知时，加入同模型、同预算的搜索或枚举规划。若方法使用额外 DOM 或可访问树，应给基线同样权限，或明确分成不同信息条件，不把额外输入的收益归给 RL。

评价单位是完整任务。定位命中率可以作为诊断指标，同时报告最终成功率、平均回报、步骤与成本、超时和失败类型。训练采样成本与推理成本分开列出；多调用模型、多重试或更长操作预算带来的差异需要独立统计。真实指标和样本规模现在均为 **【待确认】**。

## 7. 常见误解、失败条件和适用边界

| 误解或失败 | 为什么会误导 | 任务说明中的修正 |
|---|---|---|
| SR 网络有多层或迭代，所以必须 RL | 网络计算结构不等于任务级决策 | 先明确可执行动作、反馈与固定预算基线 |
| 路由标签沿用另一个项目即可 | 标签对象和输入来源可能不同 | 当前语义、合法动作与成本一律核实 |
| 未选分支没有成功记录，所以是失败 | 未观察的结果不是负例 | 反事实保持未知，另收可信反馈 |
| 单次定位好，多步保存就好 | 后续执行、状态与验证仍可能失败 | 分开报告定位与完整任务结果 |
| 截图和历史就一定是完整状态 | 隐藏变量仍可能影响后果 | 明示可观测性假设，检查同表示不同后果 |
| 教学 p=0.8 可填进真实转移表 | 人为数字不是真实测量 | 真实 p 未知就写未知 |
| 用更长预算的回报证明算法优越 | 改变了任务或资源条件 | 同预算比较，不同预算单独报告 |
| 看到成功提示就给最高奖励 | 代理反馈可能不等于持久结果 | 独立回读或可信验证；未确认则保留边界 |
| 方程成立或字段写全就说明 RL 有效 | 尚未获得真实数据与对照结果 | 明确工程草案、研究假设和 NOT_RUN |

若动作或反馈本身不清楚，先修合同；若没有真实多步影响，先选择匹配的单步方法；若环境与反馈可用，再决定是否值得承担交互、标注与计算成本。今天不要求线上探索或启动训练。
