## 1. 今天解决什么问题，与前面哪些单元有关

上一课把任务拆成观测、动作、奖励和回报。今天继续问：这些对象怎样构成一个能检查假设、复算结果的数学模型？

假设 GUI 系统收到“进入设置并保存”的任务。点击“打开设置”可能成功，也可能由于页面异常而失败；到了表单，再点“保存”仍可能成功或失败。如果只画一条成功演示路线，我们没有说明随机结果、失败退出或成本。若把截图直接叫作状态，还可能漏掉登录状态、焦点和加载阶段。

Markov Decision Process（MDP，马尔可夫决策过程）提供一套描述决策环境的语言。它要求检查“当前状态与动作是否已经包含预测下一步所需的信息”，并规定下一状态与即时奖励的概率。**把任务写成 MDP，是定义问题；它本身还不是解决问题的学习算法。**

本课用一个自然最多两步的 GUI 小环境说明联合转移核、随机轨迹和任务终止。我们枚举给定行为产生的结果，不做价值函数估计或更新。策略与探索在 RL-003 深入，价值函数在 RL-004 开始。

## 2. 学习目标

学完后应当能够：

1. 写出一个有限 MDP 的状态、合法动作、转移与奖励、折扣、初始分布和终止定义，并检查概率是否归一。
2. 通过“相同截图、不同历史、不同后果”的反例，判断状态表示是否满足 Markov 性；说明有限期限何时需要纳入状态。
3. 手算一个带随机转移的短任务，区分单步期望奖励、整段期望回报、真实终止与采集截断。

## 3. 直觉、定义和必要公式

### 3.1 一张 MDP 说明表

常见教材把 MDP 写为状态、动作、转移、奖励和折扣组成的对象。本课把初始分布和任务终止也明确列出：

| 对象 | 记号 | 含义 | 必须回答的问题 |
|---|---|---|---|
| 状态空间 | S | 本模型中所有可能状态 | 哪些变量影响未来？是否包括终止状态？ |
| 动作空间 | A，以及 A(s) | 总动作集合与状态 s 下的合法动作 | 此时哪些动作可执行？ |
| 转移概率 | P(s′｜s,a) | 执行动作后进入下一状态的概率 | 哪些后果可能发生，各占多少？ |
| 奖励说明 | R | 本课用 R(s,a) 表示单步期望奖励 | 每一步怎么计收益和成本？ |
| 折扣因子 | γ | 未来奖励的权重 | 优化什么时间尺度的回报？ |
| 初始分布 | ρ₀ | 一次任务开始时的状态分布 | 环境如何重置，起点如何采样？ |
| 终止集合 | Tₑ | 进入后本次任务结束的状态集合 | 成功、失败或放弃怎样确认？ |

S、A、P、R、γ 是常用的组成记号；ρ₀ 和 Tₑ 让一次任务的起止规则清楚。**字母 R 在本课不是回报 G，也不是任意一个模型损失。**有些文献把奖励写为 R(s,a,s′) 或直接写随机奖励分布，应先确认它的定义再读公式。

下面采用有限状态、有限动作和有限奖励取值的教学环境，并采用时间齐次模型：同一个状态与动作使用同一个环境核。Markov 性与时间齐次是需要说明的两项假设；后者并不是只靠“与历史无关”就自动成立。

### 3.2 联合核同时描述下一状态与奖励

继续沿用 RL-001 的时间下标：时刻 t 的动作 a_t，产生下一状态 s_(t+1) 和奖励 r_(t+1)。大写 S_t、A_t、R_t 表示随机变量，小写 s、a、r 表示某个具体取值。

\[
p(s',r\mid s,a)
=\Pr(S_{t+1}=s',R_{t+1}=r\mid S_t=s,A_t=a)
\]

- p：环境的**联合转移核**，给出下一状态与奖励这对结果的概率。
- s：当前状态；a：在当前状态合法的动作。
- s′：可能的下一状态；r：可能的即时奖励。
- Pr：概率；竖线表示在给定当前状态和动作的条件下。

对每个非终止状态 s 与合法动作 a，所有可能后果的概率必须相加为 1：

\[
\sum_{s'\in S}\sum_{r\in\mathcal R}p(s',r\mid s,a)=1
\]

这里的 \(\mathcal R\) 是奖励的可能取值集合，不能与期望奖励函数 R 混淆。联合核并未假设“下一状态”和“奖励”相互独立。例如，保存成功会同时产生“成功状态”和成功收益，这两个结果显然有关联。

如果只想看下一状态，把奖励取值求和：

\[
P(s'\mid s,a)=\sum_{r\in\mathcal R}p(s',r\mid s,a)
\]

如果只想看这一步的平均奖励，把所有结果按奖励加权：

\[
R(s,a)=\sum_{s'\in S}\sum_{r\in\mathcal R}r\,p(s',r\mid s,a)
\]

P 是概率，R(s,a) 是单步期望奖励。后者不包含之后还未执行的动作，不能当成整段回报。上述联合核及其边缘概率、期望奖励的关系，可对照 [Sutton 与 Barto 第二版教材原稿，CMU 正式课程托管 PDF](https://www.andrew.cmu.edu/course/10-703/textbook/BartoSutton.pdf) 第 3.1 节、式 (3.2)～(3.6)。

### 3.3 Markov 性：当前状态是否足够？

记 h_t 为到时刻 t 已发生的状态、动作与奖励历史。时间齐次 MDP 的条件可以写成：

\[
\Pr(S_{t+1}=s',R_{t+1}=r\mid h_t,A_t=a)
=p(s',r\mid S_t,a)
\]

这句话的含义是：给定当前状态和动作，再知道更早历史，不会改变下一结果的条件分布。它**不意味着未来是确定的**；随机转移完全可以满足 Markov 性。

考虑两次完全相同的设置页截图：第一次背后的账户未登录，第二次已经登录。点击“保存”后的成功概率不同。如果模型只保留截图，却让更早的登录经历改变后果，这个截图表示就没有提供足够信息。可以考虑加入当前登录或权限变量、加载阶段和必要历史，再检查是否仍有遗漏。增加历史是一种改善信息的办法，不能只凭“用了最近三帧”就证明 Markov 性成立。

观测 o_t 是智能体能拿到的信息，状态 s_t 是模型中对未来充分的表示。真实 GUI 常常只能获得部分观测；准确的说法可以是“使用截图与历史近似状态”，而不是未经检查就声称完整状态可见。

### 3.4 有限期限不能悄悄藏起来

假设任务规定“最多允许两次点击”，而且可以返回主页重试。那么相同页面在“还剩两步”与“只剩一步”时，合法动作、到期后果或可获得的回报可能不同。

解决方式之一是把剩余预算 b_t 加入状态：

\[
\widetilde s_t=(s_t,b_t)
\]

其中 b_t 是任务内剩余步数；每执行一次计入预算的动作，就按任务规则更新。也可以明确使用随时间变化的转移、动作或奖励模型，不把它误写成固定 p 的时间齐次模型。只有当阶段变量已唯一确定剩余预算时，才无需重复保存等价信息。

本课下一节的小环境没有返回或重试，流程本身自然最多两步。它不靠一个藏在模型外的“两步截止器”来结束，因此不会漏掉影响该例后果的剩余时间变量。

## 4. 手算例子：一个带随机失败的两步 GUI 环境

**所有界面、概率、收益与成本都是教学假设；没有运行真实 GUI 实验。**假设任务是打开一个表单并保存，表单的目标值已经准备好，不另计输入步骤。

### 4.1 状态、初态、动作与终态

我们使用四个状态：

| 状态 | 含义 | 本模型里的合法动作 |
|---|---|---|
| H | 主页，尚未打开表单 | open：打开表单 |
| F | 表单准备好，可以保存 | save：保存 |
| S | 保存成功，任务结束 | 不再执行真实 GUI 动作 |
| X | 执行失败，任务结束 | 不再执行真实 GUI 动作 |

表中的 S 只是“成功状态”的标签，与第 3 节表示状态空间的 S 不同；本例的整个状态空间是 {H,F,S,X}。

初态固定为 H，即 ρ₀(H)=1、其他初态概率为 0。终止集合 Tₑ={S,X}。执行 open 或 save 都花费 1 个成本单位；成功保存额外获得 10，所以成功保存这一步的净奖励为 **9**。open 失败或 save 失败都只有成本，奖励为 −1。

在这个最小例子中，每个非终止状态只有一个合法动作，因此行为已经固定。它是一个合法而退化的 MDP，用于理解环境随机性与起止规则；**不是一个需要学习动作优劣的策略优化难题**。真实应用若支持返回、取消、重试或不同保存方式，必须扩展 A(s) 与对应环境核，不能把本例的动作限制直接搬过去。

### 4.2 联合转移表

| 当前状态与动作 | 下一状态 s′ | 即时奖励 r | p(s′,r｜s,a) |
|---|---|---:|---:|
| H, open | F | −1 | 0.80 |
| H, open | X | −1 | 0.20 |
| F, save | S | +9 | 0.75 |
| F, save | X | −1 | 0.25 |

未列出的结果概率为 0。每个当前状态与动作组分别相加为 1，不能把整张表所有行加起来要求为 1。表中两组各对应一个不同的条件分布。

单步期望奖励为：

\[
R(H,\mathrm{open})=0.80(-1)+0.20(-1)=-1
\]

\[
R(F,\mathrm{save})=0.75(9)+0.25(-1)=6.5
\]

这并不表示从 H 开始的回报是 −1，也不表示每次保存都得到 6.5。实际保存得到 9 或 −1，6.5 是这些可能结果的平均。

### 4.3 枚举完整轨迹，而不是只看成功演示

给定行为是“在 H 执行 open；如果到 F，再执行 save”。取 γ=0.9，沿用前课的折扣回报。

| 完整结果 | 概率 | 奖励序列 | G₀ |
|---|---:|---|---:|
| 第一步失败，H→X | 0.20 | [−1] | −1 |
| 打开后保存失败，H→F→X | 0.80×0.25=0.20 | [−1,−1] | −1+0.9×(−1)=−1.9 |
| 打开后保存成功，H→F→S | 0.80×0.75=0.60 | [−1,+9] | −1+0.9×9=7.1 |

三个完整结果的概率和为 1。期望回报是把完整回报按完整轨迹概率加权：

\[
\mathbb E[G_0]=0.20(-1)+0.20(-1.9)+0.60(7.1)=3.68
\]

还可以直接从“第二步只有 0.80 的机会发生”来核对：−1+0.9×0.80×6.5=3.68。若忽略打开失败的 0.20，就会把第二步奖励当成总能获得，从而算错。

这个行为的成功率是 0.60，期望动作数是 1+0.80=1.80。若 γ=1，三种回报变成 −1、−2、8，期望回报是 4.2；也等于成功期望收益 10×0.60 减期望成本 1.80。

**这些数值是对指定模型和指定行为的手算，不是训练结果、最优策略结论或真实 GUI 成功率。**没有比较新算法，也不能把本课的 3.68 与上课另一个教学环境的 6.2 当作算法性能对比。

## 5. 与前一种方法或概念的关系

本课并未引入新算法。它把 RL-001 的口头决策描述变成可以逐项检查的环境模型。

| RL-001 已建立的概念 | 本课增加的约束 | 得到什么，又付出什么 |
|---|---|---|
| 观测与状态 | 检查对未来是否充分 | 能讨论 Markov 性；需要识别隐藏变量 |
| 选择动作 | 明确每个状态的合法动作 | 避免执行不可能动作；要维护动作接口 |
| 获得奖励 | 写出下一状态与奖励的联合核 | 不能把有关联的结果随意拆开；模型可能未知 |
| 累积回报 | 明确初态、随机轨迹与终止 | 能完整枚举小环境；复杂环境难以列全 |

真实任务通常不知道精确 p。写出 MDP 并不要求事先掌握全部转移概率；它要求你说明这些变量、依赖与任务规则。我们今天给定概率，是为了可以独立复算。后续算法会讨论如何在未知环境或有限数据下学习。

知道模型时还可以直接规划、枚举或执行可靠规则；这些是应比较的基线。采用 MDP 语言，不会自动证明需要深度 RL。

### 终止、吸收与重置

本例进入 S 或 X 后，真实任务结束。为了统一数学求和，可以给每个终态 z 增加一个仅用于数学记账的 idle 动作：

\[
p(z,0\mid z,\mathrm{idle})=1,\quad z\in T_e
\]

它只回到自身并产生 0 奖励，称为吸收约定。这个虚拟动作不是新增的 GUI 点击，也不增加实际任务长度。**进入成功状态那一步仍然获得 9，只有终止之后追加的奖励才是 0。**下一次任务通过 ρ₀ 重置开始；重置不是当前任务里的一个获益动作。

### 真实终止与采集截断

任务定义中的成功、失败，或明确写进任务的期限结束，可以产生 `terminated`。采集器为了控制数据量或墙钟时间提前停止，而真实任务仍可继续，是 `truncated`。最后一条已采集数据不自动等于终止状态。

任务内有限期限影响结果时，需要把剩余时间或预算纳入表示，或使用明确的时间相关模型。采集截断则保留真正的最后观测与截断原因；自动重置后的新观测不能配到上一任务的动作上。两者对后续学习目标的影响，会在价值估计与 TD 单元讨论，今天不推导更新公式。[Gymnasium 官方时限文档](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)明确区分这两种信号。

## 6. 主要应用：先把多步 GUI 执行合同写清楚

这一节是**工程推断和拟议建模**；真实研究实验**未运行**。使用 MDP 语言的目的，是知道该记录什么、怎样判断任务成功，以及哪些假设仍有缺口。

| 项目 | 一个可检验的多步 GUI 设计 | 需要核实的条件 |
|---|---|---|
| 观测或状态 | 指令、截图、允许使用的历史；必要的焦点、加载和剩余预算 | 实际能获取哪些变量，是否足以预测后果 |
| 动作 | 点击、输入、滚动、返回、结束及参数 | 合法动作集合、坐标系、文本权限和执行语义 |
| 转移 | 动作造成页面与任务进度变化，也可能失败或延迟 | 执行器反馈、异步状态、重置与随机性 |
| 奖励 | 独立成功收益减操作与资源代价 | 成功是否真正保存到系统，而不只是出现提示 |
| 反馈来源 | 环境结果、持久状态回读或可信人工核查 | 结果的真实性、延迟、噪声和复核办法 |
| 时间结构 | 多个动作改变后续可见信息和可选操作 | 任务内预算、外部采集截断分别记录 |
| 数据 | 指令、决策前观测、历史、合法动作、执行动作、结果、奖励及终止信号 | 防止未来信息泄漏，保留重置与最终观测 |
| 评价 | 完整任务成功率、步骤数、非法动作率、失败/截断比例、端到端时延与成本 | 同一任务分布、相同执行权限和固定预算 |
| 训练成本 | 环境交互、重置、反馈验证与样本筛选 | 样本量、执行调用、标注和计算预算 |
| 推理成本 | 每步视觉或文本模型调用，加执行和等待 | 每个任务总调用数、费用、显存、p50/p95 时延 |

**先比较的非 RL 基线：**固定流程或有限状态机、规则加监督控件定位、同一初始模型的示范学习策略；若转移模型已知，还可以使用枚举或搜索规划。评价须使用相同初态分布、任务目标、输入权限和动作预算。一次控件定位的命中率有用，但不能替代多步任务的最终成功率。

本课小环境的流程已固定，因此规则执行足够。真实环境若有返回、重试、取消或多条路径，才出现值得分析的动作选择问题；若隐藏信息太多，需要讨论部分可观测模型或历史表示，而不是继续声称截图天然是 Markov 状态。

**其他两个方向的边界：**单次模态路由若没有后续动作影响，先讨论监督或 Contextual Bandit；若调用图像后可以继续获取信息、重试或改变预算，再明确多步状态和动作。SR 的单次重建仍可先用监督基线；只有提出迭代、停止或计算分配等可执行决策后，才建立对应状态、转移与质量—计算成本目标。本课不替实际模态标签作定义，也不提出已验证的 SR 增益。

## 7. 常见误解、失败条件和适用边界

| 误解或失败 | 本课的纠正 | 实际检查 |
|---|---|---|
| Markov 就是没有随机性 | 它要求当前状态充分，不要求结果确定 | 同一条件下可以有多个后果 |
| 用了截图就有完整状态 | 截图是观测，可能遗漏登录、焦点或加载 | 构造相同截图不同后果的反例 |
| P 与奖励可以随便独立采样 | 下一状态和奖励可能相关 | 保留联合结果或合理的条件奖励模型 |
| R(F,save)=6.5 就是每次奖励 | 它是单步平均；实际是 9 或 −1 | 逐轨迹计算，再求期望 |
| 每张转移表所有行和为 1 | 每个当前状态—动作组分别归一 | 分组检查概率质量 |
| 两步上限无需表示 | 任务期限影响结果时，剩余预算可能是状态的一部分 | 区分自然两步流程、任务内期限和外部截断 |
| 保存成功后持续得到 +9 | 成功收益只在到达时给一次 | 吸收后奖励为 0，防止重复计收益 |
| 最后一条日志就是 terminal | 可能只是采集停止 | 保留 `terminated`、`truncated` 与最终观测 |
| 把任务写成 MDP 就证明 RL 有效 | MDP 是问题定义，方法还需基线与验证 | 明确数据和 NOT_RUN 状态 |

如果输入权限、动作语义、奖励真实性或任务边界尚不清楚，先完善执行与评价合同。把不确定条件明确记下来，比为不清楚的任务选择算法更有用。

## 参考答案（练习完成后再看）

**题 1。** 仅截图没有满足题目中的 Markov 性，因为相同截图和同一动作的后果还依赖截图未包含的账户状态。可以加入真实可获取的登录、权限等变量，并检查焦点、异步加载、页面历史、剩余预算等是否也影响未来。对候选表示，考察在相同表示与动作下，按不同历史分组时后果分布是否仍不同；若不同就有遗漏。有限数据里未发现差异，不等于证明现实系统严格 Markov。历史或记忆可以帮助，但不自动提供充分状态。

**题 2。** 首步失败概率 0.20，奖励 [−1]，G₀=−1；第二步失败概率 0.80×0.25=0.20，奖励 [−1,−1]，G₀=−1.9；成功概率 0.80×0.75=0.60，奖励 [−1,+9]，G₀=7.1。γ=0.9 时期望回报为 0.20×(−1)+0.20×(−1.9)+0.60×7.1=3.68。成功率为 0.60，期望动作数为 0.20×1+0.80×2=1.80。γ=1 时期望回报为 0.20×(−1)+0.20×(−2)+0.60×8=4.2。结果依赖给定教学环境和固定行为，没有训练或比较算法，不能声称方法提升。第一步失败的任务不会执行第二步，不能无条件加上 6.5 的第二步期望奖励。

**题 3。** A 中期限是任务定义的一部分；在允许重试的环境中，相同页面可能对应不同剩余步数，而合法动作或到期后果不同。应把剩余预算纳入状态，或明确采用时间相关的有限期限模型；预算耗尽后的任务失败可以是实际终止。B 中只是外部采集截断，最后的真实状态仍可能继续转移，不能自动设为 terminal 或断言后续回报为 0。应保留终止与截断的不同信号、真正的最后观测和停止原因；后续学习方法再按这些语义处理，不把新一次 reset 的观测误接到旧任务。
