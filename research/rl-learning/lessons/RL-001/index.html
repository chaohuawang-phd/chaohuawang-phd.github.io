1. 今天解决什么问题，与前面哪些单元有关

你已经熟悉用训练数据、模型和损失函数完成预测任务。开始学强化学习（Reinforcement Learning, RL），最容易犯的错误是先问“这个问题能不能用 PPO”，然后为算法拼出一套奖励。我们先反过来：任务中有什么可以选择的动作？动作会产生怎样的结果？我们希望改善哪个可观测的目标？

假设用户提出一个问题，系统可以选择只使用文本，也可以调用一个图像分支。另一个场景中，GUI 智能体可以点击“设置”，再选择子菜单，最后完成一个目标。这两者都有选择，但结构不同：前者可能只需要一次选择；后者前面的动作会改变后面看到的界面和可选动作。一次选择和长期决策不能自动使用同一套方法。

本课是课程起点。它为 RL-002 的 Markov Decision Process（MDP）问题建模、RL-004 的价值函数、RL-005 的 Bellman 方程打基础。今天先理解交互、策略、奖励与回报；MDP 的严格条件和数学模型放在下一课。

今天最核心的判断是：先把任务写成决策问题，再判断需要监督学习、Bandit，还是多步 RL。这是后面分析 SR、模态路由和 GUI 时一直保留的检查。

2. 学习目标

学完后，你应当能够：

  1. 用自己的话区分智能体、环境、观测、动作、策略和奖励，并解释为什么一张截图未必是完整状态。
  2. 计算一个短轨迹的折扣回报，区分“这一步奖励高”和“整体策略的期望回报高”。
  3. 为一个研究任务写出最小决策说明，并依据反馈形式和时间依赖选择应先比较的非 RL 基线。

判断是否掌握的标准是你能独立完成第 8 节练习，并说明自己的假设。阅读完成或 PPT 已生成，都不自动等于理解已确认。

3. 直觉、定义和必要公式

3.1 从一次预测到一个交互循环

监督学习通常给模型一个输入和目标标签，用预测误差更新参数。RL 则让智能体（agent）选择动作，与环境（environment）发生交互，并根据获得的奖励学习如何选择。环境可以是可执行的 GUI、模拟器或能返回反馈的决策系统。RL 也可以从以前记录的交互数据学习；“训练时必须在线操作真实系统”并不是定义要求。

先把时间步想成一次决策时刻。本课采用以下记号：

环境给出观测 o_t
        ↓
策略 π 选择动作 a_t
        ↓
执行动作，环境发生变化
        ↓
得到奖励 r_(t+1) 和下一观测 o_(t+1)
        ↓
继续下一步，或结束本次任务

这里的奖励编号采用教材常见约定：在时刻 t 执行动作，接着收到 r_(t+1)。某些资料把同一个奖励写为 r_t；只要一套公式内保持一致，两种记号都可以。

概念 本课记号 含义 GUI 例子
智能体 agent 作出决策的系统 根据任务指令操作界面的模型
环境 environment 动作产生后果并返回反馈的系统 应用程序及其执行状态
状态 s_t 建模时用于预测环境后续变化的信息 界面、页面栈、登录状态、加载状态等
观测 o_t 智能体实际上能看到的信息 当前截图及允许使用的历史
动作 a_t 此刻可选择并执行的决策 点击某坐标、输入文本、滚动、结束
奖励 r_(t+1) 对动作结果的数值反馈 每步成本 −1，任务成功额外获得收益
策略 π 从可用信息到动作的规则 给各个可执行动作分配概率
一次任务 episode 从开始到结束的一段交互 从收到指令到成功、失败或超时

“当前截图”是观测，不应不经检查就当作完整状态。两张一样的截图背后可能有不同的页面历史、异步请求或账户权限，下一步结果也可能不同。实际策略可以使用 o_t，也可以使用历史信息 h_t = (o_0, a_0, …, o_t)。状态是否满足 Markov 条件，下一课再检查。

3.2 策略是动作选择规则

随机策略可以写成：

at∼πθ(⋅∣ot)a_t \sim \pi_\theta(\cdot \mid o_t)at​∼πθ​(⋅∣ot​)
  • a_t：当前动作。
  • π：策略；π(a | o) 表示在观测 o 下选择动作 a 的概率。
  • θ：可学习的参数，例如神经网络权重。
  • “∼”：按概率分布采样。
  • “·”：表示这里填入任意一个合法动作。

例如 π(文本分支 | o)=0.7、π(图像分支 | o)=0.3。这里的 0.7 是动作选择概率，并不是文本分支回答正确的概率。把“路由概率”“回答置信度”“正确率”混为一谈，会让后面的奖励和评估都失去含义。

确定性策略总是给出同一个选择，可以写成 a_t=μ_θ(o_t)。策略不一定是神经网络：手写规则、阈值和表格也都可以定义策略。

3.3 奖励和回报是两个量

奖励描述一次反馈。回报（return）把从某个时间步开始的一串奖励合起来。本课用有限长度的折扣回报：

Gt=∑k=0T−t−1γkrt+k+1G_t = \sum_{k=0}^{T-t-1}\gamma^k r_{t+k+1}Gt​=k=0∑T−t−1​γkrt+k+1​
  • G_t：从时刻 t 开始的回报。
  • T：本次任务结束的时间索引，最后一个动作是 a_(T−1)，最后一个奖励是 r_T。
  • k：从当前时刻向后数的步数，当前动作产生的奖励不折扣。
  • γ（gamma）：折扣因子，常用 0≤γ≤1。
  • γ^k：第 k 个未来奖励在当前目标中的权重。

有限任务可以使用 γ=1，此时回报就是奖励总和。若使用无限长度的折扣总和，常见做法是 γ<1，并对奖励作有界等条件，以保证收敛。γ 应当反映你选择的目标；它不是必须随便填的“稳定训练参数”。本课尚不讨论平均奖励目标。

如果一个正确的 GUI 操作先经过两步成本，再完成目标，早期奖励可能为负，整体回报仍然为正。只按当前一步奖励选动作，可能会停在任务起点。

3.4 我们最终优化的是策略的期望回报

J(π)=Eτ∼π[G0]J(\pi) = \mathbb{E}_{\tau \sim \pi}[G_0]J(π)=Eτ∼π​[G0​]
  • J(π)：策略的整体目标值。
  • τ（tau）：一次轨迹，包含任务内的观测、动作和奖励。
  • E：期望；对初始任务、策略采样和环境随机性等取平均。
  • τ∼π：在给定环境中按策略 π 产生轨迹。

一个轨迹运气好，不足以证明策略好；某个训练指标上涨，也不足以证明实际业务目标改善。我们要比较同一任务分布下的平均表现与不确定性。具体的价值估计和统计验证会在后续单元展开。

上述交互术语、策略与回报的基础定义可对照 OpenAI Spinning Up：Key Concepts in RL。本课的业务设计与算例为原创教学分析，不来自该资料的实验。

4. 手算例子：先算目标，再讨论学习算法

4.1 单步模态路由：收益必须包含成本

例子性质：教学假设。它不代表你的实际输入来源、标签含义、正确率或业务代价；没有运行实验。

假设同一个请求允许两个动作，执行后即结束：

  • 文本分支：回答正确概率为 0.70，固定成本为 0.5。
  • 图像分支：回答正确概率为 0.90，固定成本为 2.0。
  • 回答正确收益为 10；回答错误收益为 0；无论正确与否都支付分支成本。

定义动作的净奖励：

r=10 1{回答正确}−c(a)r = 10\,\mathbf{1}\{\text{回答正确}\} - c(a)r=101{回答正确}−c(a)

其中 1{回答正确} 是指示函数：正确取 1，错误取 0；c(a) 为执行动作 a 的成本。期望奖励是正确概率乘正确收益，再减固定成本。

动作 正确时奖励 错误时奖励 期望奖励
文本分支 10−0.5=9.5 −0.5 0.70×10−0.5=6.5
图像分支 10−2=8.0 −2.0 0.90×10−2=7.0

在这组已知且固定的教学条件下，选图像分支的期望奖励更高。两者差值为 0.5。若图像成本增加到 2.5，二者期望奖励恰好相同；若更高，文本分支更好。准确率最高的动作未必在所有成本设定下都最优。

但我们还没有解决“怎么学”：真实环境中，每个请求的正确概率往往未知。如果每个训练请求都评估过两个分支，就有两种动作结果；如果只记录了实际被选择分支的结果，另一个动作的结果是缺失的。后者是 Bandit 反馈，不是两个动作都带标签的普通训练数据。不能把未选择的分支自动标为失败。

在单步、没有跨请求动作影响的设定下，Contextual Bandit 通常比多步 MDP 更贴合结构。若两种动作的收益函数已经可靠已知，直接比较期望收益就能决策，未必需要额外训练一个 RL 算法。

停下来用 2 分钟检查：如果正确收益从 10 改为 5，两个动作分别是多少？你应当得到 3.0 和 2.5，并发现最优动作发生变化。这个变化来自目标定义，而不是算法名称。

4.2 多步 GUI：局部成本与最终成功

例子性质：教学假设；不是实际 GUI 数据或实验结果。

假设一个三步轨迹的奖励为 r_1=−1、r_2=−1、r_3=+10，γ=0.9，则：

G0=−1+0.9×(−1)+0.92×10=6.2G_0 = -1 + 0.9\times(-1) + 0.9^2\times 10 = \mathbf{6.2}G0​=−1+0.9×(−1)+0.92×10=6.2
步骤 奖励 折扣权重 对 G_0 的贡献
第 1 步 −1 1 −1
第 2 步 −1 0.9 −0.9
第 3 步 +10 0.81 +8.1
合计 6.2

若 γ=1，G_0=8；若 γ=0，G_0=−1。这不是说 γ=1 永远最好，而是说明改变 γ 就改变了对后续结果的权重。没有任务成功收益时，一个“每步扣分”的智能体可能偏向不操作或提前结束，因此奖励必须对齐完整任务。

本课只计算给定轨迹的回报。如何把最终成功归因给早期动作、如何估计还未发生的后续收益，是价值函数、TD 和策略梯度将解决的问题。

5. 与已经熟悉的监督学习有什么关系

这是第一课，因此没有前一种 RL 算法需要比较。我们以你熟悉的监督学习为参照。

比较点 监督学习的常见设定 RL 的常见设定
训练信号 输入配目标标签 所执行动作产生的奖励或已记录交互
学习目标 降低预测损失 提高策略的期望回报
动作后果 通常不改变本条样本的目标 可能改变后续观测、动作和反馈
反馈完整性 目标标签通常给定 经常只看到已选择动作的结果
数据分布 常以固定数据集为起点 可能随策略改变
主要额外困难 泛化、噪声、偏移等 加上探索、反馈缺失、长期归因和评估偏差

这是一组常见结构差异，并非互斥分类。例如监督模型可以作为策略的初始参数；离线 RL 使用固定交互数据；若人工标签覆盖了所有动作结果，成本敏感监督学习可能是很强的基线。

RL 的潜在价值在于学习“应该做什么及其后果”，特别是结果不直接给出正确动作、或者一个动作会改变未来时。代价是你要定义可信的反馈、解决探索和采样成本，并检查模型是否只是在利用奖励的漏洞。

6. 主要应用：先把模态路由写清楚

这一节是工程推断与建模草案；任务资料尚未确认，研究实验未运行。本课仅假设“选择处理分支”，不擅自规定你的 0/1 标签，也不假设图像一定来自电视截屏、摄像头或其他来源。

6.1 一页决策说明

必须说明的项目 本课示例 正式落地前还需核实
观测或上下文 问题文本、允许使用的历史、输入可用性 输入来源、哪些特征决策时真实可见；是否有泄漏
动作 选文本分支或图像分支 可调用的真实分支、缺失输入时的合法动作

反馈来源 人工核查或可信任务结果 如何验证结果，反馈延迟，噪声与标注一致性
时间结构 一次选择后结束 是否有“获取信息→再决定”、重试或跨请求资源影响

6.2 先比较哪些基线

建议以同样的输入权限和评价目标比较：

  1. 固定文本分支与固定图像分支：确定收益和成本的基本边界。
  2. 可解释业务规则或阈值：检查任务能否由简单条件解决。
  3. 监督路由分类器：当真实路由标签定义明确、训练和业务目标相容时使用。
  4. 成本敏感监督模型：有充分的动作结果数据时，预测各分支收益或错误风险，再据成本选择。

如果只有已选择动作的反馈，直接把其余动作当负例会引入偏差。若不同请求互不影响、回报立即给出，下一阶段重点考虑 Contextual Bandit；只有动作改变了后续决策，才需要具体讨论多步 RL。非 RL 基线和 RL 应当使用一致的任务分布、输入信息和成本统计。

6.3 为什么 GUI 与 SR 今天只作结构判断

GUI 的一次控件定位，若有正确框或坐标，可以先用监督定位模型并报告定位误差或点击命中率。多步 GUI 操作则需要可恢复的执行环境、任务成功验证与轨迹记录；成功率、平均步骤、超时率和非法动作率更接近完整目标。前者与后者的反馈与评价单位不同。

SR 中把低分辨率图像映射为高分辨率图像，本身可以是监督重建问题。若要考虑 RL，应当先提出可选择的决策，例如受计算预算约束的早停、迭代次数或区域计算分配，再说明动作怎样影响质量和成本。比较固定计算预算的监督 SR 模型与简单自适应策略；报告质量—计算成本关系。提高 SR 性能只是目标描述，尚未给出一个 RL 决策问题，更未给出新方法或实验增益。

这些判断属于工程分析，不是已发表应用证据。后面的专题会检索与具体问题对应的原始论文，再建立可以验证的方案。

7. 常见误解、失败条件和适用边界

误解或失败 为什么会出问题 检查方法
有一个评分就一定需要 RL 评分也可用于监督评估或直接优化 写出动作、反馈缺失和时间依赖
截图就是完整状态 隐藏变量可能影响下一步 构造“同图不同历史”的反例
奖励数值高就代表业务更好 代理评分可能被利用，成本可能漏算 独立验证实际成功与成本
每步都最好就会最终成功 短期成本可能换来长期收益 用完整轨迹回报检查
没调用的分支就是错误分支 其结果是未知，不能自动补标签 区分全动作反馈与 Bandit 反馈

同一算法适合三个研究方向 任务结构、动作与反馈不同 分别完成决策说明与基线比较

实际采用 RL 至少需要：目标可验证、动作合法且可执行、能获得足够的反馈或可信离线数据、评价不依赖训练奖励单一代理、试错和计算成本可接受。若这些条件暂不满足，先建设数据与评估流程也是有效进展。

8. 三道理解题：先独立作答

请用约 8 分钟回答。答案在本文最后。记录不确定之处，比只对照最终数值更有帮助。

题 1｜把任务拆成决策。 你训练一个模型，输入截图和“找到保存按钮”，输出一个坐标。训练集提供正确坐标，但没有应用执行环境。说明它的观测、输出和训练信号。它目前是否必须作为 RL 问题？如果扩展为“修改设置并确认保存”，新增哪些信息与反馈才能讨论多步 RL？

题 2｜手算回报并解释目标。 某三步 GUI 轨迹的奖励为 [−1, −1, +10]。分别计算 γ=0.9 和 γ=1 的 G_0。另一个策略立即结束，得到奖励 0。在已给定的两条确定轨迹里，γ=0.9 时哪个回报更高？说明为什么这仍然不能证明该策略在真实任务分布上更好。

题 3｜路由、成本与缺失反馈。 假设正确收益 10、错误收益 0。文本分支正确概率 0.70、成本 0.5；图像分支正确概率 0.90。图像成本达到多少时二者期望净收益相同？若日志仅记录实际选择文本分支后的结果，能否据此把图像分支标为失败？应优先补充什么日志信息和非 RL 基线？

参考答案（练习完成后再看）

题 1。 观测是允许使用的截图和文本指令，输出是坐标，训练信号是正确坐标或定位框。它目前可以直接作为监督定位任务；输出能被解释为动作，不代表训练已经是 RL。要讨论“修改设置并保存”的多步过程，需要可执行且能重置的环境、每步合法动作、执行后的观测或历史、终止条件、任务成功验证、过程成本和轨迹日志。只用某一帧的目标坐标不足以判断整个任务是否成功，也不能假设沿用原示范轨迹时后续坐标始终有效。

题 2。 γ=0.9 时 G_0=−1−0.9+8.1=6.2；γ=1 时 G_0=−1−1+10=8。给定两条确定轨迹，γ=0.9 时完成任务轨迹的回报 6.2 高于立即结束的 0。但真实环境中可能存在失败、任务差异和策略随机性；这是一条假设成功轨迹，必须比较同一真实任务分布下的期望回报、成功率、成本和不确定性。不能把一次成功当成整体性能证据。

题 3。 文本期望净收益为 7−0.5=6.5。图像期望净收益为 9−c，因此令 9−c=6.5，得到 c=2.5。若只有选中文本的结果，图像结果缺失，不能自动标为失败。应记录决策前上下文、实际合法动作集合、行为策略实际选择概率（如果可以正确获得）、选中动作的结果、反馈定义与延迟、调用成本；有条件时在独立评价集评估各动作，但不要虚构反事实结果。先比较固定分支、规则/阈值、监督路由和成本敏感监督基线，再根据反馈与时间结构决定是否使用 Contextual Bandit 或多步 RL。
